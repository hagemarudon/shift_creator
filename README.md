# バイトのシフト作成（試作版）

Googleフォームで集めた「出勤できる時間」を読み込み、時間帯ごとの必要人数を満たすシフトを自動で作ります。
フォームは `google_forms/forms.gs` で作ったものでも、ほかの人が作った質問の形や順番が違うものでも読めます。時間刻み（初期値30分）も画面で変えられます。
自動作成には Google の OR-Tools（CP-SAT）を使っています。画面とシステムの作りは [timetable_creator](https://github.com/hagemarudon/timetable_creator) にそろえています。

## 使い方

```bash
pip install -r requirements.txt
streamlit run app.py              # 画面で使う（http://localhost:8501）
python cli.py 回答.csv 出力.xlsx    # 画面なしで使う
python make_sample.py             # サンプルの回答を作り直す
python -m pytest tests            # テスト
```

## 流れ

1. [google_forms/README.md](google_forms/README.md) の手順で、期間と営業時間に合わせたフォームを作り、スタッフに送る
2. 回答が集まったら、アプリで回答を読み込む
   - 回答のスプレッドシートを「ファイル → ダウンロード → カンマ区切り形式（.csv）」か「Microsoft Excel」で保存してアップロード
   - または下の「回答を自動で読み込む」を設定すれば、アプリを開くだけで最新の回答を読む
3. ほかの人が作ったフォームなら「回答の読み方」で列の使い方を確かめる
4. 左側で時間刻み・期間・祝日・勤務の長さ・必要人数を確かめる。必要なら「日ごとの指定」で、日ごとに入れたい人・入れない人を選ぶ
5. 「シフトを作る」を押す
6. 「シフト表」「日別」「個人別」「集計」「人数不足」「日ごとの指定」で確かめ、Excelでダウンロードする

## 入力（フォームの回答）

Googleフォームの回答シート（`フォームの回答 1`）をそのまま読みます。

| 列 | 内容 |
| --- | --- |
| 氏名 | 必須。フォームでは「名簿」シートから選ぶプルダウン。同じ氏名で2回以上答えたときは最後の回答を使う（空白の有無・全角半角は区別しない）。「氏名」を含む列が2つあるとき（記述式からプルダウンに作り直したとき）は、空でないほうを使う |
| 出勤できる時間 [10:00-10:30] | チェックボックス（グリッド）の回答。値は「11/16(月), 11/17(火)」のように選んだ日付 |
| 期間中に入れる最大日数（任意） | 見出しに「最大日数」を含む列 |
| 期間中の希望勤務時間（任意） | 見出しに「希望勤務時間」を含む列 |
| 備考（任意） | 見出しに「備考」か「要望」を含む列（アプリは読むだけで使わない） |

グリッドは、行と列のどちらか一方が時刻（`10:00` `10:00-10:30` `10時〜11時`）、もう一方が日付（`11/16(月)`）なら向きはどちらでも読めます。
`10:00-11:00` のように1時間ずつ聞いた場合も、その時間にかかる枠すべてを出勤できるとみなします。`10:00` だけの見出しは、次の見出しまで（1時間おきに聞いていれば1時間）とみなします。
日付に年がなければ、回答のタイムスタンプに一番近い年にします（12月に1月分を聞いても大丈夫です）。

## ほかの人が作ったフォームを読む

質問の見出しや順番、聞き方が違うフォームでも読めます。読み込むと、列ごとの「使い方」を見出しと中身から推測し、画面の「回答の読み方」に出します。違っていれば選び直してください。

| 使い方 | 内容 |
| --- | --- |
| 氏名 | 2列以上（姓と名など）にすると、つなげて1つの氏名にする |
| 出勤できる時間 | 日付・時刻が入っている列。下の形が読める |
| 最大日数・希望勤務時間・上限時間 | 数字の列（「8時間」「5日」も読める） |
| 備考 | 2列以上あればつなげる |
| 回答日時 | タイムスタンプ。年の決め方と、同じ人の答え直しの順番に使う |
| 使わない | メールアドレス・学年など |

出勤できる時間は、選んだ選択肢・グリッドの行の見出し・質問の見出しから日付と時刻を探して組み合わせます。

| フォームの聞き方 | 例 |
| --- | --- |
| 時刻×日付のグリッド（このアプリのフォーム） | `出勤できる時間 [10:00-10:30]` に `11/16(月), 11/17(火)` |
| 日付ごとの質問に時間帯の選択肢 | `11/16(月)に入れる時間帯` に `10:00-12:00, 14:00-16:00` |
| 日付ごとの質問に「終日OK」「入れない」 | `11/17(火)` に `終日OK`（一日中）・`入れない`（読まない） |
| 日付と時刻の行に ○× | `シフト希望 [11/18(水) 10:00-14:00]` に `○`（`×` `不可` は読まない） |
| 入れる日と入れる時間帯を別々に | `入れる日` に `11/16(月), 11/18(水)`、`入れる時間帯` に `10:00-14:00` → その組み合わせ |
| 入れる日だけ | `入れる日` に `11/16(月)` → その日は一日中出勤できるとみなす（注意が出る） |

時刻は `10:00` `10時半` `午後1時〜3時` `10:00 AM` も読めます。「休み希望」「出勤できない日」のように出勤できない日を聞く質問は読みません。

「午前のみ」「1限」のように日付・時刻として読めない選択肢は、「回答の読み方」の「選択肢の読み替え」に出ます。
`9:30-12:00`（時刻）、`終日`、`×`（出勤できない）などを書くと、そのとおりに読みます。

「この条件を既定にする」を押すと、列の使い方（推測と違うものだけ）と読み替えも `config.local.toml` に保存され、次に同じフォームを読むときに使われます。
見本は `sample/ほかのフォームの回答サンプル.csv` です（「午後のみ」を読み替えると全部読めます）。

ほかの人のフォームの回答を読むには、次のどれかにします。**フォームのURL（`docs.google.com/forms/…`）からは回答を読めません**（貼ると、どうすればよいかの案内が出ます）。

1. フォームを作った人に、フォームの「回答」タブの「スプレッドシートにリンク」でスプレッドシートを作ってもらい、その「共有」を「リンクを知っている全員」（閲覧者）にしてもらう。アプリの「Googleスプレッドシート」の「回答のURL」に、そのスプレッドシートのURLを貼る（設定はいらない。URLを知っている人は誰でも回答を見られるので、URLは広めない）
2. そのスプレッドシートを「ファイル → ダウンロード → カンマ区切り形式（.csv）」で保存してもらい、「ファイル（CSV・Excel）」から読み込む
3. スプレッドシートを編集できるなら、下の「回答を自動で読み込む」の A（Apps Script）も使える

## 時間刻み

画面の左側の「時間刻み」で 15分・30分・60分・120分 から選べます（`config.toml` の `slot_minutes` が初期値）。シフトの開始・終了はこの刻みでそろいます。

- 枠は必要人数の一番早い開始から刻みごとに作る（60分で9:30開始なら 9:30, 10:30, …）。必要人数の時刻と勤務の長さは刻みに合わせる（合っていなければエラーが出る）
- フォームの刻みより粗くしてもよい。フォームが30分・アプリが60分なら、10:00-11:00 の枠には 10:00-10:30 と 10:30-11:00 の両方に答えた人だけを入れる
- フォームの刻みより細かくしてもよい（フォームが1時間・アプリが30分なら、その1時間の中で30分ずつ入れられる）
- 重みは30分あたりなので、刻みを変えても同じ重さで効く

見本は `sample/フォーム回答サンプル.csv`（架空のスタッフ20人・2週間）です。

画面の「スタッフ」で、使う回答（「使う」のチェックを外した人はシフトに入れない）と、責任者の印・最大日数・希望時間・上限時間を人ごとに直せます。

## 日ごとの指定（入れたい人・入れない人）

画面の「日ごとの指定」は、スタッフ×日付の表です。セルで「入れたい」「入れない」を選びます（「－」は指定なし）。
氏名は読み込んだ回答の氏名がそのまま並ぶので、フォームの名前と食い違うことはありません。

- **入れない**：その日はその人を入れません（必ず守る）。人数が足りなくなっても入れません
- **入れたい**：その日、その人がフォームで出勤できると答えた時間の中で、なるべく入れます。人数不足をうめるほうを優先するので、最大日数などの都合で入れられないこともあります
- 「入れたい」にした日にその人の出勤できる時間がないときは、作る前に注意が出ます。入れられなかった人は、作ったあとの注意と「日ごとの指定」タブ（Excelの「日ごとの指定」シート）に出ます
- 指定は、期間を変えたりスタッフの「使う」を外したりしても消えません。アプリを開き直すと消えます

### フォームの氏名を名簿にそろえる

フォームの氏名を記述式にすると、「山田」「山田太郎」のように同じ人が別の名前で答えて、別の人として読まれてしまいます。
`google_forms/forms.gs` では、スプレッドシートの「名簿」シートに書いた氏名から選ぶプルダウンにしています。手順は [google_forms/README.md](google_forms/README.md) の「名簿」にあります。

## 守るルール

必須（必ず守る）
- 出勤できる時間にだけ入れる。営業時間（必要人数が1人以上の時間）の外には入れない
- 1日に入るのは1回（連続した勤務）まで。長さは「最短」以上「延長上限」以下
- 最大日数・上限時間を超えない
- 日ごとの指定で「入れない」にした人は、その日に入れない

優先（点数で調整、重みは `config.toml` の `[weights]`）
1. 必要人数の不足をなくす（最優先）
2. 日ごとの指定で「入れたい」にした人を、その日に入れる
3. 責任者を入れる（「営業中はいつも責任者を1人以上入れる」をオンにしたとき）
4. 1回の勤務は「原則」の長さ（初期値 2時間）まで。超えるのは、人数が足りない時間帯をうめるときだけ
5. 人数を多くしすぎない / 勤務時間を人によって偏らせない / 希望勤務時間に近づける / 出勤日を少なく

足りない時間帯は「人数不足」に、その時間に出勤できる人数と一緒に出します。

## 条件の入力

| 項目 | 内容 |
| --- | --- |
| 期間 | 回答に出てくる日付から自動で入る。短くしてもよい |
| 祝日として扱う日 | 「平日」「土日祝」「日祝」の当てはめに使う |
| 時間刻み | 15・30・60・120分 |
| 1回の勤務（時間） | 最短・原則・延長上限（時間刻みの倍数） |
| 必要人数 | 曜日・開始・終了・人数の表。下の行ほど優先（同じ時間帯は下の行で上書き）。曜日は `毎日` `平日` `土` `日祝` `土日祝` `月水金` `11/23` など |
| 責任者 | 営業中はいつも責任者を1人以上入れるか |
| 優先条件の重み | 上の優先ルールをどれだけ重視するか |

「この条件を既定にする」を押すと `config.local.toml` に保存され、次回から最初に入ります（Gitで管理しません）。`config.toml` は全員共通の初期値です。

## 出力

| シート | 内容 |
| --- | --- |
| シフト表 | スタッフ×日付。セルは「10:00-12:00」。右端に日数と合計時間。土曜は青、日祝は赤の見出し |
| 日別 | 日ごとに、人×枠（時間刻み）のマスを塗った表。延長した勤務はオレンジ、下の行は配置人数／必要人数（不足は赤） |
| 個人別 | 1勤務1行（氏名・日付・開始・終了・時間・延長） |
| 集計 | 人ごとの出勤日数・合計時間・延長した日・出勤できる時間 |
| 人数不足 | 足りない時間帯 |
| 日ごとの指定 | 指定した人と日付、実際の勤務、指定どおりになったか（指定したときだけ） |

Googleスプレッドシートから読んだときは、元のスプレッドシートに「シフト表」「個人別」「集計」「人数不足」「日ごとの指定」シートを書き込めます。

## 回答を自動で読み込む

CSVをダウンロードしてアップロードしなくても、アプリを開くだけで最新の回答を読み込めるようにする方法です。どちらか1つを設定します。

### A. Apps Script のウェブアプリ（おすすめ・Google Cloud 不要）

回答のスプレッドシートに小さなスクリプト（`google_forms/responses_api.gs`）を付け、合言葉付きのURLで回答を渡します。
手順は [google_forms/README.md](google_forms/README.md) の「アプリに回答を自動で渡す」にあります。できたURLを Secrets に入れます。

```toml
[responses]
url = "https://script.google.com/macros/s/xxxx/exec?key=合言葉"
```

「元のGoogleスプレッドシートに書き込む」で、作ったシフトを同じスプレッドシートに書き込めます。URLは合言葉を含むので、人に教えないでください。

### B. サービスアカウント

Google Cloud でサービスアカウントの鍵（JSON）を作れる場合の方法です。組織のポリシー（`iam.disableServiceAccountKeyCreation`）で鍵を作れないアカウントでは使えないので、A にしてください。

1. [Google Cloud コンソール](https://console.cloud.google.com/) でプロジェクトを作り、「APIとサービス → ライブラリ」で **Google Sheets API** を有効にする
2. 「IAMと管理 → サービスアカウント」でサービスアカウントを作り（ロールは不要）、「キー → 鍵を追加 → JSON」でダウンロードする（合鍵なので人に送らない）
3. 回答のスプレッドシートの「共有」で、JSONの `client_email` を **編集者** で追加する
4. Secrets に入れる（`gcp_service_account_json` は `[responses]` より上に置く）

```toml
gcp_service_account_json = '''
{ ダウンロードしたJSONの中身をそのまま }
'''

[responses]
url = "https://docs.google.com/spreadsheets/d/xxxx/edit"
```

### Secrets の入れ場所

- Streamlit Community Cloud：アプリの「Settings → Secrets」
- 手元：`.streamlit/secrets.toml`（Gitで管理しない）

「ファイル → 共有 → ウェブに公開」したURLや、「リンクを知っている全員」に共有したスプレッドシートのURLを `url` に入れても（画面の「回答のURL」に貼っても）読めますが、URLを知っている人は誰でも回答を見られます。

## Googleスプレッドシートから読む（Googleログイン）

上の設定をしていないときは、使う人がそれぞれGoogleでログインして読むこともできます。設定は timetable_creator と同じです。
Google Cloud で Google Sheets API を有効にし、OAuth クライアント（ウェブ アプリケーション、リダイレクト URI はアプリのURL）を作って、secrets に書きます。

```toml
[google_oauth]
client_id = "xxxx.apps.googleusercontent.com"
client_secret = "xxxx"
redirect_uri = "http://localhost:8501"
```

## 構成

- `shift/loader.py` 設定とフォームの回答（CSV・Excel・スプレッドシート）の読み込み（列の使い方の推測・選択肢の読み替え）、必要人数の計算
- `shift/solver.py` シフトの自動作成（OR-Tools）
- `shift/output.py` 表の作成と Excel への書き出し
- `shift/google_sheets.py` スプレッドシートの読み書き（Apps Script・サービスアカウント・Googleログイン・ウェブに公開したCSV）
- `shift/settings_io.py` 画面で入力した条件の保存
- `google_forms/forms.gs` 出勤できる時間を聞く Google フォームを作る（Apps Script）
- `google_forms/responses_api.gs` 回答をアプリに渡し、シフトを書き戻すウェブアプリ（Apps Script）
- `app.py` 画面（Streamlit）／ `cli.py` コマンドライン版
